## 约定

1. **事实以代码为准**，文档只是快照——冲突时改文档，不改认知。
2. **规则在 `.workbuddy/skills/delivery-protocol/`**。本仓库**没有** `.trae/`，那是 V5 的。
3. **取舍只记在 `docs/decisions.md`**，同一个问题不重复讨论第二遍。
4. 过时的断言必须**删掉或标为已证伪**，不允许"留个参考"——它会在半年后误导排期。
5. **常读文档有行数上限**：超了就拆开或移入 `docs/archive/`。记录性文档不限长，但不放在常读路径上。

## 代码放哪（判据）

| 目录 | 放什么 | 判断方法 |
|---|---|---|
| `lib/core/` | 与界面无关的能力：数据、更新器、插件运行时、纯函数 | 这段逻辑能不能在**别的 App** 里复用？能 → core |
| `lib/app/` | v6 外壳：页面、状态、路由、装配 | 只服务本 App 的界面与装配 → app |

`lib/app/` 可以依赖 `lib/core/`，反过来不行。

**测试目录按被测概念分，不强制镜像 `lib` 路径**。例：`CurrencyStore` 在
`lib/app/state/`，测试在 `test/core/currency/` —— 因为它是"货币"这个概念的测试。
按源码路径去找会找不到，按概念找才对。

## 已证伪的断言（**不要再引用**）

这些说法在旧文档/旧路线图里存在过，已被实测推翻：

| 断言 | 为什么错 |
|---|---|
| 「拓展包以独立 asset 包存放，**运行时动态加载 + 热插拔**」 | Flutter release 把 Dart AOT 成机器码，**没有运行时加载 Dart 代码的机制**（`deferred` 仅 web 有效） |
| 「核心包控制在 **2MB** 以内」 | 实测 arm64 APK 21MB = `libflutter.so` 12MB + `libapp.so` 8MB + 其余。引擎减不动，下限约 13MB |
| 「多个模块**打包为独立库**，避免主库体积过大」 | Flutter 没有"可运行时加载的 Dart 库"这种东西，见第一条 |
| 「多平台支持：**iOS**」 | `ios/` 只有 `flutter create` 骨架，从未构建。iOS 已放弃 |
| 「V6 读 `update_v6.json`」 | 分仓前的老方案，**没落地**。V6 读本仓库根 `update.json`，V5 那份在 `note_study` |
| 「引流的入口写死对方的版本号」 | 5.5.29 / 6.0.3 起改成**读对方的清单**，否则改一次就要两边各发一版 |

> 测试环境若遇到 `WebSocketException: Invalid WebSocket upgrade request`，
> **先清代理变量**（`env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy NO_PROXY=127.0.0.1,localhost`）。
> `CreatePipe ERROR_PIPE_BUSY` 是另一个偶发问题，别混为一谈。

## 归档区里有什么

`docs/archive/` 只放**历史记录**，进了就不再改。按类型分三个子目录：

| 子目录 | 放什么 | 什么时候有用 |
|---|---|---|
| `design/` | 4 篇已实现的设计文档：编辑面板、可换首页、设置与备份、V5→V6 升级 | 想改这块功能、先看当初的取舍 |
| `acceptance/` | 10 篇已签收的验收清单（2026-10-26 ~ 10-29） | 追溯某次交付验了什么 |
| `handoff/` | 1 篇过期交接说明（2026-10-28） | 想接上一段中断的工作 |

**判据**：这份文档描述的东西（功能、版本、一次交付）**已经结束了**，就是归档的时候；
描述的东西还在被改，就留在 `docs/` 根。

**已证伪**的内容不进归档，只在上面的表里留一行"曾这么写过、为什么错"。

## 时间戳（2026-10-31 起的约定）

**新写或修改 `docs/` 里的文档时，在标题下面加一行**：

```
> 最后更新：2026-10-31
```

理由："上次改动是什么时候"决定了这份文档值不值得信 —— 尤其在这种靠对话推进的
项目里，一份三个月没动过的设计文档和一份昨天改过的不该同等对待。

**不回填旧文档**：补日期只能靠猜，猜错了比没有更糟。

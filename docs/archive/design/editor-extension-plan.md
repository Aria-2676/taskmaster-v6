# 编辑面板：字段归主包，插件只提供整页

> 2026-10-26 ｜ 状态：**已实现**（`lib/core/field/`、`field_manager_page.dart`、`task_editor_page.dart`）
> 上一版（字段 DSL / 插件贡献字段 / 槽位列）**全部作废**，原因见 §5。

## 1. 分工

| 东西 | 谁拥有 | 用户怎么改 |
|---|---|---|
| 字段（有哪些、什么类型、默认值） | 主包 `FieldCatalog` | 不能改，只能开关/排序/改默认值 |
| 字段的值 | `tasks` 表的真实列 | 编辑页填 |
| 编辑页的外观与交互 | 主包内置弹层/全屏 | 设置项切换 |

**插件不贡献字段，也不参与渲染**。它提供的是**一整个已经画好的页面**（WebView），
要么从侧边栏进去，要么直接当首页（见 `home-mode.md`）。

为什么这么切：字段一旦能参与排序/筛选/统计，就必须是真实列 + 索引；
放到插件侧（JSON 或 EAV 表）等于放弃这些能力。而"加字段需要配套逻辑代码"这件事，
插件也给不出解法 —— 逻辑必须跑在编译期代码里。

## 2. 字段表

`lib/core/field/task_field.dart` 的 `FieldCatalog.all`：

| id | 类型 | 锁定 | 默认 |
|---|---|---|---|
| `title` | 文本 | ✅ 必填 | — |
| `due_date` | 日期 | ✅ | 今天/当前选中日 |
| `priority` | 枚举（红橙黄蓝白） | | `white` |
| `tags` | 多选 | | 空 |
| `description` | 多行文本 | | 无 |
| `estimated_minutes` | 枚举（不设/15/30/60/120） | | 无（不设） |

**加一个字段 = 库里加一列（可空）+ 这里加一条**。编辑页、字段管理页、默认值解析
全部由表驱动，没有第二处要改。

## 3. 三个约定（最容易做错的地方）

1. **null ≡ 字段默认值**。用户清空和"从没设过"是同一个状态，不设哨兵、不做三态。
   "明确不要"用值域里的成员表达（时长「不设」是 `''`，不是 null）。
2. **默认值：新建时落库，编辑时不回填**。这两件事必须分开，
   一开始合成了一条"绝不回写"，结果用户设了默认 60 分钟、新建任务卡片上不显示时长，
   看起来就是"设置没生效"。
   - 新建：没动过就按默认值写库 —— 设默认就是想要这个结果。
   - 编辑：没动过就保持原值（null 还是 null）—— 否则改一次默认值、
     再打开一次老任务，历史数据就被悄悄改写了。
3. **只有用户亲手改过默认值，编辑页才标「默认」**。没改过就不标 ——
   优先级那种永远有值的字段挂个牌子纯噪音。

配套：关掉的字段如果这条任务里**确实有内容**，编辑页底部会提示
「已隐藏 描述（内容还在）」，点一下临时展开。不然用户会以为数据被开关删了。

## 4. 形态：主体 + 容器

同一份 `TaskEditorContent`，两种外壳：

- **底部弹层（默认）**：`DraggableScrollableSheet`，初始 62%，可上拖到全屏，右上角一键切换。
- **全屏页**：`TaskEditorPage`，保留 AppBar（返回手势落在系统栏位置）。

调用方只有 `showTaskEditor()` 一个入口，形态由 `settings.ui.editor_form` 决定。
弹层左上角是 X 不是「取消」——同一个屏幕上出现两个「取消」会分不清取消哪个。

**弹层的三个关闭开关全部关掉**，原因都是"改动不能静默丢"：

| 参数 | 值 | 不关会怎样 |
|---|---|---|
| `DraggableScrollableSheet.shouldCloseOnMinExtent` | `false` | 往下拉一把，整个路由被 pop，改了一半的内容没了，且绕过「放弃修改？」 |
| `showModalBottomSheet.isDismissible` | `false` | 点遮罩直接关，同上 |
| `showModalBottomSheet.enableDrag` | `false` | 模态层和内部 sheet 抢手势，从满屏下拖会直接关掉而不是收到 62% |

尺寸只留两档：`minChildSize = initialChildSize = 0.62`，`maxChildSize = 1`，
`snap: true`。往上拖到满屏，下拉回 62%，再往下就停住 —— 关闭只剩 X 一条路。

## 5. 已作废的方案（不要再提）

| 方案 | 为什么废 |
|---|---|
| 插件在 `plugin.json` 里声明字段（DSL） | 字段需要配套逻辑，插件给不了；且排序筛选要索引 |
| 插件字段值存 `plg_*` 表再 join | 每个插件一次 join，索引另维护，插件代码跑不进模型层 |
| 在 `tasks` 预留 `fx_*` 槽位列给插件用 | 槽位只解决"插件加字段"，而这条路已经去掉，空列是纯负担 |
| `tasks.extra` JSON 存自定义字段 | JSON 没法建索引，等于这些字段只能看不能用 |

## 6. 还没做

- **bridge 写权限**：现在插件只能读（`task:read` / `tag:read`）。
  备忘录不需要；"todo 模式"要改主任务就绕不过去，需要权限声明 + 白名单方法。
- **按字段参与的排序/筛选**：字段已经是真实列，SQL 侧随时能加，界面上还没有入口。

## 7. 默认值踩过的坑（别再合回去）

第一版把"默认值只在读时生效、绝不回写"当成一条规则，结果是：设了默认 60 分钟，
新建任务仍然没有时长，卡片上什么都不显示。用户的判断是"这功能没做"，
而不是"这是刻意的设计"。

正确的切分是按**创建 / 编辑**分，不是按"要不要回写"分：

| | 没动过的字段 | 动过的字段 |
|---|---|---|
| 新建 | 写默认值 | 写用户选的值 |
| 编辑 | 保持原值（可能是 null） | 写用户选的值 |

同一个按钮（保存）在两种模式下的语义不同，这一点写在 `_save()` 的注释里了。

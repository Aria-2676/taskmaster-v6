# M1 界面层决策

这一份只记**决定与理由**，不记实现细节。改之前先读，别凭印象推翻。

前提（已经在别处定死，不再讨论）：
- v6 是**新 App**，不要求数据兼容 v5。v5 的行为规格（`spec-*.md`）是**参考**，不是契约。
- 不引入 React Navigation（V9 裁决），自写栈导航。
- 状态管理用 Zustand（已装 5.0.15）。

---

## 一、v5 的哪些行为**不沿用**

这是本文件最重要的部分。v5 的一些行为是历史包袱，
**照抄会把包袱带进新 App，而且新用户完全不需要这些约束**。

| v5 行为 | v6 决定 | 理由 |
|---|---|---|
| 列表 `LIMIT 50` | **去掉** | 本地数据量本来就小，硬截断只会让人以为「数据丢了」。真遇到性能问题再加分页。 |
| 月视图缓存 LRU=3 | **不做** | Zustand 直接算，本地数据量下没有缓存的必要；多一层缓存就多一处过期 bug。 |
| 循环任务补填窗口 | **保持现状，不要动** | ⚠️ 我曾在这份文档里写过「要限制在 90 天窗口内」——**那是错的，我没核实就下了结论，已更正**。实际实现是 `RECURRENCE_WINDOW_DAYS = 15`（now 当天 → now+15 天），**上界本来就有限**。v5 的真实缺陷在**无下界**：旧模板会从很早的日期逐日回补，生成一堆历史孤儿实例。要修得动 `generateInstanceDates` 的下界，属 M2 范畴，M1 不动。 |
| 回收站 10 条上限（超出自动裁剪） | **保留，但做成设置项**，默认 10 | 行为本身合理（避免无限堆积），但不该写死。 |
| 逾期判定边界 = 当天 00:00 | **沿用** | 这是**正确的语义**，不是包袱。「过了排期日就算逾期」符合直觉。 |
| `loop_id` 格式 | **沿用** | 已在 v5 验证过，改动没有收益只有风险。 |
| `enabledCreateFields` / `enabledEditFields`（用户可选显示哪些字段） | **沿用** | 这是**好功能**，用户能精简表单。不是包袱。 |
| 优先级五档 红/橙/黄/蓝/白 | **沿用** | 注意：**没有黑色**，白色是最低档（不是「未设置」）。 |

## 二、导航模型

- **三个底部 Tab**：任务 / 积分 / 我的
- **页面栈压在 Tab 之上**；切 Tab 会重置该 Tab 的栈
- 跨 Tab 压栈（如任务页压出商城）→ 切到那个 Tab 并把它的栈重置为「首页 + 目标页」
- **底部栏只在 Tab 首页显示**，压栈页面与弹窗时隐藏
- Android 返回键：先弹栈，栈已在首页才交还系统退 App

约束（来自 `src/repo/types.ts`，**不是我编的**）：
```
Priority   = 'red' | 'orange' | 'yellow' | 'blue' | 'white'   // 无黑色
Recurrence = 'none' | 'daily' | 'weekly' | 'monthly'          // 无 yearly
PomodoroMode = 'work' | 'shortBreak' | 'longBreak'
```

## 三、主题

- 三档：`system`（跟随系统）/ `light` / `dark`
- **所有颜色一律从 `src/ui/theme.ts` 取**，界面里不许出现写死的十六进制
- 优先级的黄、白两档在浅底/深底上都有可读性问题，
  所以 `priorityIndicator()` 返回的是 `{color, border}` 而不是单个颜色——**白档必须画描边**才看得见
- ⚠️ 主题模式目前**只存在内存**，未接 settings 表（`src/state/themeStore.ts` 里有 TODO）。
  重启会回到 `system`。接线时只改那一处。

## 四、状态分层

```
界面组件  →  Zustand store  →  src/repo 仓储  →  SQLite
```

**铁律：界面与 store 都不许自己写 SQL。**
`src/repo/` 下五个仓储是经过验证的（84 条单测 + `tool/` 下两个验收脚本），
在 UI 里另写一套 SQL 等于绕过所有验证，尤其是回收站那条 V6 三步规则——
那是踩过真坑的地方（误用 `recycled_tasks.id` 会静默删掉活任务的标签关联）。

## 五、页面清单与优先级

按「让用户最早见到能用的 6」排序，不是按实现难度：

1. **任务列表**（Tasks Tab 首页）— 按日期看任务、完成/取消完成（联动积分）、删除
2. **新增/编辑任务** — 标题/描述/日期/优先级/奖励积分/循环/单词任务
3. **积分页**（Points Tab 首页）— 余额 + 流水
4. **商城** — 商品列表、兑换、仓库（已兑换）
5. **我的**（Profile Tab 首页）+ **设置** — 主题、番茄钟、开发者入口
6. **回收站** — 恢复 / 永久删除
7. **标签管理**
8. **任务详情**

## 六、Spike 控制台不能丢

`App.tsx` 现在是 Spike 验收控制台，有四块面板：OTA（检查/下载/回滚 + 三次启动不健康自动回滚）、
通知、番茄钟前台计时、金样本验收。

**这些是真机验证过的能力，不能因为换 UI 就删掉。**
做法：真实 App 顶上来，这四块收进**设置 → 开发者面板**（路由 `DevPanel`），不暴露给普通用户。

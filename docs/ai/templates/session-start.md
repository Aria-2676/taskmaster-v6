# 开工卡（每轮开始填一次）

> 最后更新：2026-11-01

协调者（用户）每轮开始给这四行。**只写第一行也能开工**，其余走默认，但 agent 要在交付时
写明"我假设了什么"。

## 1. 协调者给什么

| # | 给什么 | 必给 | 不给时的默认 |
|---|---|---|---|
| 1 | **任务**：一句话说清这轮做什么 | 是 | —— （agent 按 `docs/ROADMAP.md` §9 自己选，可能不是你今天想要的） |
| 2 | **授权**：推不推、发不发版 | 否 | 只提交不推送；发版一律等明确指示 |
| 3 | **红线**：不许碰什么 | 否 | 按 `docs/conventions/` 判；跨 owner 的改动先问 |
| 4 | **验收口味**：这轮要不要真机项 | 否 | 平台层（弹层/键盘/通知/后台）默认真机，其余转自动化测试 |

一行版（够用）：

```
任务：番茄钟——主包计时引擎 + 到点通知
授权：可以推送，不发版
红线：别改插件契约版本
验收：模拟器即可，真机项我来跑
```

## 2. agent 自己查什么（不要问用户）

开工先跑这几条，把结果贴回来当"开工体检"：

```bash
adb devices                                  # 模拟器/真机在不在线
git status --short                           # 工作区干不干净
grep '^version:' pubspec.yaml                # 当前版本
git rev-parse --short origin/main            # 远端到哪了
```

再加自检两条（`docs/conventions/delivery.md` §3）：

```bash
flutter analyze lib
flutter test                                 # 记总数，对比上轮只增不减
```

- **查不到就直说**：设备不在线、代理挂了、git 推不动，都要在开工时讲明，不要假设。
- 环境类状态不需要用户报；只有 agent 查不到的才问（用户手上真机的版本、上一轮是否已签收、
  是否允许动线上资产）。

## 3. 收工回执

```
改了什么：<1-3 条>
证据：<测试名 / 命令输出 / 文件:行号>
没验证：<真机 / 边界 / 未复现>
验收清单：docs/acceptance/<日期>-<主题>.md，共 N 条
```

协调者只需回「全过」或「B3 不过」。不过的编号回到实现，改完重跑自检再交。

## 4. 与其它文档的关系

- 角色与分工：`docs/conventions/collaboration.md`
- 交付与推送纪律：`docs/conventions/delivery.md`
- 任务 claim 文件：`docs/ai/templates/task-claim.md`（非平凡任务必须先建）

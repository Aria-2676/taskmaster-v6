# 2026-11-25 任务提醒验收

## 做了什么

任务可以设一个提醒时间（`yyyy-MM-dd HH:mm`），到点弹通知。dbVersion 2 → 3。

## 人判定（模拟器）

| # | 操作 | 预期 | 实测 |
|---|---|---|---|
| 1 | 编辑任务 | 底部有「提醒」行 | ✅ 显示 `2026-11-25 07:12` |

通知 id `32770` = `0x8002`，即 task id 2 + 0x8000 偏移，和番茄钟（0x7071/0x7072）不冲突。

## 期间踩的三个坑

**① 回收站整行拷贝，少一列直接崩**

删除任务是把 `tasks` 的一行 map 直接搬进 `recycled_tasks`。只给 tasks 加列，
第一次跑测试就报 `table recycled_tasks has no column named remind_at`。
两张表必须同步加列 —— 迁移里也是两次 ALTER。

**② 迁移测试只建了一张表**

`v6_migration_test` 手工造的 v1 库里只有 `recycled_tasks`，迁移往 `tasks` 上 ALTER
时报「表不存在」。真实老库必然有 tasks，测试补上了这张表的 v1 DDL。

**③ 通知权限没授予时静默无提示**

第一次到点什么都没发生 —— Android 13+ 的 `POST_NOTIFICATIONS` 没授予，
通知被系统直接丢掉，日志里连错都没有。手动 `pm grant` 之后才响。

修法：**设提醒的那一刻**请求权限（用户此刻的意图明确，弹权限框最讲道理），
而不是启动时弹。没授权的后果是"到点静默"，用户只会觉得这功能没用。

## 另一处顺手修的

编辑页底部（提醒那一行）被系统导航栏压住，看得到点不到。ListView 底部 padding 28 → 88。

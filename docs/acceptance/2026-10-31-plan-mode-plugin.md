# 验收清单：首页模式插件化 + 第一个模式插件「计划模式」

> 最后更新：2026-10-31

本轮做了三件事：
1. 契约里加 `home` 声明（**不是准入**，只决定默认开不开 + 模式叫什么名字）；
2. 快捷切换的存法从"收起集合"改成"默认值 + 只记偏离默认的覆盖"，带 6.0.4 数据迁移；
3. 新插件 `plan_mode`（周计划 → 模式名「计划模式」）。

**没上真机**，只在 `flutter test` 里跑过（562 通过）。手感项（B3 底部动作层的
高度、B4 挪动后的滚动位置）必须真机看。

前置：插件市场里能装到「周计划」（随包资产，断网也能装）。

### 查出的问题：快捷切换的弹层点不动（已改成对话框）

现象：点顶栏箭头弹出底部弹层后，**点哪一行都没反应**，只是把弹层关掉。
返回键能关、widget test 全过、`flutter analyze` 干净 —— 只有真机点才现形。

查法：在 `onTap` 里打一行日志，发现点「计划模式」时日志是
`[mode] tap builtin` —— **热区比画面整体偏下约 166px（≈55dp）**，
点什么都命中上一行。换 `Column`、去掉 `showDragHandle`、去掉 `SafeArea`
三种写法都复现，说明是 `showModalBottomSheet` 在这台 Android 17 上的
画面/热区错位，不是我们的布局写错了。

改法：换成**居中对话框**（`showDialog` + `Dialog`）。同一个位置点下去，
日志变成 `[mode] tap plugin:plan_mode`，首页立刻切过去。
对话框在这台机器上坐标是准的，4 项以内一屏看完也不比从底部弹上来慢。

> 这条是这次上模拟器最大的收获：**"看得见"不等于"点得着"**。
> 那一版在 6.0.4 里已经发出去了，等于用户的快捷切换一直是废的。

### 补充：计划模式下原本没有新建入口（插件 1.2.0 修）

用户一句话问到点子上：**「周计划的情况下不能添加新的计划？」** 确实不能 ——
沿用了 10-27 那条"插件模式下不画 `+`"，而那条规定是为**通用页面插件**写的
（主包不知道插件里"新建"是什么意思）。计划模式是任务的另一种看法，没入口就是缺陷。

修法不是让主包画 `+`（那会把 10-27 的规则推翻，且对日记类插件是错的），
而是**插件自己提供**：每一天末尾一个虚线按钮「＋ 这天加一条」，日期已经定了，
只填标题，调 `task.create` 落到那天。

| # | 操作 | 可观察预期 |
|---|---|---|
| B9 | 计划模式页 | 每一天末尾都有「＋ 今天加一条 / ＋ 这天加一条」，虚线、比任务浅一档 |
| B10 | 点「＋ 今天加一条」 | 弹输入层，副标题写「今天 · 10月31日」，输入框自动聚焦，键盘弹起后输入层在键盘上方 |
| B11 | 输入标题 → 添加 | 任务立刻出现在那一天，计数 +1，顶部「x/y 已完成」跟着变，提示「加好了」 |
| B12 | 切回任务模式看今天 | 这条任务在列表里 —— 插件写的是主包的数据，不是自己存了一份 |

模拟器实测（2026-10-31 21:59）：B9~B12 全部通过。**App 版本没动（还是 6.0.4），
插件从 1.1.0 升到 1.2.0 就生效** —— 又一次验证了"插件不需要发版"。

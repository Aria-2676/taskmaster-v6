# 文档地图

> 每个主题**只有一个权威来源**。这里说明谁负责什么、什么时候该读。
> 2026-10-22 首版。

## 约定

1. **事实以代码为准**，文档只是快照——冲突时改文档，不改认知。
2. **规则只在 `.trae/rules/`**，其他文档只引用不复述。
3. **取舍只记在 `docs/decisions.md`**，同一个问题不重复讨论第二遍。
4. 过时的断言必须**删掉或标为已证伪**，不允许"留个参考"——它会在半年后误导排期。
5. **常读文档有行数上限**：超了就拆开或移入 `docs/archive/`。文档越长，读的人越容易看漏一条。
   记录性文档（版本历史、决策流水）不限长，但不放在常读路径上。

## 已证伪的断言（**不要再引用**）

这些说法在旧文档/旧路线图里存在过，已被实测推翻：

| 断言 | 为什么错 |
|---|---|
| 「拓展包以独立 asset 包存放，**运行时动态加载 + 热插拔**」 | Flutter release 把 Dart AOT 成机器码，**没有运行时加载 Dart 代码的机制**（`deferred` 仅 web 有效，AOT 无反射） |
| 「核心包控制在 **2MB** 以内」 | 实测 arm64 APK 23MB = `libflutter.so` 12MB + `libapp.so` 8.5MB + 其余 2.5MB。引擎减不动，下限约 13MB |
| 「多个模块**打包为独立库**，避免主库体积过大」 | Flutter 没有"可运行时加载的 Dart 库"这种东西，见第一条 |
| 「多平台支持：**iOS**」 | `ios/` 只有 `flutter create` 骨架，**无 Podfile.lock、从未 pod install、从未构建**。iOS 已明确放弃 |
| 「V6 读 `update_v6.json`」 | 那是分仓之前的方案，**没落地**：`update_v6.json` 在本仓库从未存在过（`git log --all` 查过）。分仓后 V6 读本仓库根 `update.json`，V5 那份在 `note_study` |

> 测试可正常跑。若遇到 `WebSocketException: Invalid WebSocket upgrade request`，
> **先清代理变量**（`env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy NO_PROXY=127.0.0.1,localhost`），
> 细节见 `CLAUDE.md` §2。`CreatePipe ERROR_PIPE_BUSY` 是另一个偶发环境问题，别混为一谈。

## 为什么保留 `docs/archive/`

旧内容不是"没用"，而是**不该出现在常读路径上**：留着会误导排期，删了又丢上下文。
所以分两类处理：

- **已证伪** → 删掉，只在本文件留一行"曾这么写过、为什么错"
- **历史记录**（旧版本变更、旧规划） → 移入 `docs/archive/`，只读不改

## 为什么 `CLAUDE.md` 不设行数上限

行数上限保护的是**人**——一次读完就能拿全，不会漏。但 `CLAUDE.md` 主要由 agent 整体读取，
拆成两份反而多出一个失败点：**得先记得"还有第二份要读"**。漏读一份的代价，远大于多读 100 行。

所以它保持单文件，但内容仍按「每次动手都要知道」这条筛选；纯发版类的细节优先精简，
不因为"反正能读"就什么都往里塞。

其余常读文档（`README`、`INDEX`、三份平台文档、规则卡）仍受上限约束——那些是给人看的。

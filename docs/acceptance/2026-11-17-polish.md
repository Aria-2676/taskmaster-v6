# 2026-11-17 一批体验修复（逾期 / 勾选 / 反馈 / 刷新 / 示例）

对应 2026-11-16 用户报的六条。每条都写明"验到什么程度"，
没验到的不写成验过了。

## 一、逾期按今天算，不按选中日期算

**根因**：`TaskStore.load()` 里 `_overdue = overdueBefore(_day)`，
`_day` 是当前查看的日期。翻到 11-20 时，11-17~11-19 未完成的任务全被标成逾期。

**改法**：改用注入的 `clock()`（生产 = `DateTime.now`）。

| # | 操作 | 预期 | 实测 |
|---|---|---|---|
| 1 | `overdue_test` 新增用例「翻到后天看：后天之前的任务不算逾期」 | 只有昨天那条算逾期 | ✅ 单测通过 |
| 2 | 全量 | 653 条全过 | ✅ |

**未手动验证**：模拟器上翻日期看逾期块。逻辑由单测锁住，但没在界面走一遍。

## 二、计划模式的任务能勾了

原来是刻意只读（`check` 灰 0.5、没 handler，注释写"避免两份真相"），
但界面上是复选框，点了没反应。改成调主包 `task.setDone`。

| # | 操作 | 预期 | 实测 |
|---|---|---|---|
| 1 | 计划详情 → 点任务前的复选框 | 出现 ✓、文字划掉 | ✅ |
| 2 | 同上 | 进度从 0% 变 100%，计数 0/1 → 1/1 | ✅ |
| 3 | 失败的路径 | toast 出原因，不静默 | 代码路径，未构造失败场景 |

## 五、插件升级后不再复用旧离屏页面

`acquire` 以前只看"内存里有没有实例"，不看它在哪个目录。插件升级后目录变成
`id/新版本/`，旧页面还活着 → 查的是上一版逻辑。

改法：记录 `loadedPath`，路径变了就 release 重建。

**未直接验证**：要验证得先复现"升级后今日页仍用旧版查询"，
成本高；改动是"路径不一致就重建"，逻辑直白。

### 期间踩到的坑

第一版 `seedShelfInner` 里写了 `await loadLists()`，真实函数叫 `reloadLists()`。
JS 调不存在的函数要运行时才炸，`node --check` 查不出来（语法完全合法），
表现是按钮永远停在「载入中…」。数据其实插进库了，只是最后一步刷新失败。

已修，并给两个插件都加了 try/catch（失败 toast 原因 + 恢复按钮）。
另外加了个粗检查脚本：把插件里 `await xxx(` / `return xxx(` 和 function 定义对一遍，
当前三个插件都干净。

## 没做的

- **日记**没加示例：日记是私人内容，塞假记录反而让人不适；它的界面也足够直白。
- **整页插件当首页时**（比如把计划模式设为首页），从今日页勾完任务回首页，
  插件页不会自动重载 —— 重载 webview 会丢滚动位置、打断番茄钟计时，
  风险大于收益，这轮没做。

# 2026-10-27 验收：V6 成为正式入口

按定案「V5 数据不对接 V6，全部舍弃」做的三件事：

| 改动 | 文件 |
|---|---|
| 主入口换成 V6（不写演示数据、检查更新） | `lib/main.dart` |
| 旧入口另存为对照 | `lib/main_v5_legacy.dart` |

## 一、需要你判断的（2 条）

| # | 路径 | 操作 | 预期 | 不过时先看 |
|---|---|---|---|---|
| A1 | 全新安装（或清数据） | 看首启 | 接受「空列表 + 这一天还没有任务」，不觉得"应用坏了" | `v6_home_page.dart` `_EmptyState` |
| A2 | 与 V5 对比 | 想一遍现在缺的东西 | 接受「先上 V6，积分/商城/番茄钟/统计/小组件等插件补齐」 | `docs/self-update-v5-to-v6.md` §六 |

A2 是这轮唯一有实质风险的决定：V6 现在的功能比 V5 **少**，升级对用户是"降级体验"。
如果这个不能接受，那就不能现在发版，要等插件。

## 二、没验证的（如实列出）

| 项 | 为什么没验 | 什么时候验 |
|---|---|---|
| 更新弹窗真的会弹 | 本地版本 6.0.0 已高于清单 5.5.26，按逻辑不该弹；要验必须把清单改成更高版本，而那会让所有 V5 用户点到死链 | 发版时：先传 6.0.1 的包，再把清单写 6.0.1，用一个旧包装上去看是否提示 |
| 签名一致性 | 只能看 `key.properties` 指向的路径，实际指纹要和已发布 APK 比对 | 构建 release 时用 `apksigner verify --print-certs` 对比 |
| 覆盖安装能否成功 | 需要真实 release 包 + 真机上的旧版 | 同上 |

---

## 三、发布前必须做的顺序

1. `flutter build apk --release`（确认签名是 `D:\Dev\keystore\` 那把）
2. 把 4 个产物传到 GitHub Release `v6.0.0`
3. **之后**改 `update.json`：`latest.version` → `6.0.0`，`downloads` 换成新包的 url/sha256/sizeBytes
4. 更新说明里必须写明：**升级后旧任务不会出现在 V6 里**

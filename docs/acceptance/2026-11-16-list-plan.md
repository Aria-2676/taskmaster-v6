## 未验证（如实记录）

- **中文输入**：模拟器只能 `adb input text` 打 ASCII，名字都用的英文。中文名字的实际显示/输入没验。
- **长列表**：清单条目 > 20 条、计划阶段 > 10 个的滚动与性能没压过。
- **改期**：弹层能打开、点确定不报错，但**没能确认任务日期真的变了**（任务本来就在今天，改成同一天看不出差异）。
- **`where` 传整数 0 查不到**：计划插件用 `where status=0` 查进行中计划恒为空，改前端过滤才通。宿主 `select` 的单测里同样条件能查到（已补测试锁住），
  所以不是 `_where`/`_valuesParam` 的显式 bug，具体成因未定位。清单的 `list.pending` 也已改成前端过滤规避。

## 订正：「插件页吞触摸」这个结论是错的（2026-11-16 下午查清）

上午记过一条"统计页里 Flutter 控件点不动"，结论写错了，两条真实原因：

1. **底栏坐标一直算错**：底栏中心在 y≈2190，我一直点 2080（缩略图坐标 ×2 的估算），
   落在底栏上方的内容区，所以"点了没反应"。改成 2190 后每次都灵。
2. **一直在测旧包**：模拟器上装的是 preview 风味（versionCode **10110**），
   `flutter build apk --release` 产的是 **6110**，`adb install -r` 一直报
   `INSTALL_FAILED_VERSION_DOWNGRADE` 失败，而我只看 `tail -1`（空行）没注意。
   于是"新包的行为"其实全是旧包的。**先 `adb uninstall` 再装**，或者构建 preview 风味。

所以没有"webview 覆盖底栏"这回事，PluginPage 的布局不用查。

**未验证**：

- **数字跟着变**（0% → 50%）：要加阶段才能改百分比，但计划插件详情页的
  「+ 加阶段」「+ 排入任务」点了没反应（见下），所以没改成数据。验到的是
  "每次重拉都拿最新数据"，没验到"数据变了块里的百分比跟着变"。

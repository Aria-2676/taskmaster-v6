## 当前批次（A 批 · 现在就能做，约 5 分钟）

### A1 · 导出真实数据库，做成真金样本 ★最高价值★

**为什么必须你做**
真机上装的是 Flutter **release** 包，`run-as` 读不了它的私有目录（会报 `package not debuggable`）。
而我手上那份 `fixtures/golden-v3.db` 是**我合成的**——它覆盖了各种边界（孤儿行、NULL 状态、月末、超长文本），
但它不是你真实使用过程中攒出来的数据，**没有真实的循环任务实例分布、没有真实积分流水、没有真实的历史脏数据**。

真库能暴露合成样本造不出来的问题。最典型的一个我已经预判到了：
循环任务生成窗口**没有下界**，模板日期久远时会从旧日期一路回补——
2020 年的每日任务模板会一次性生成 **2000+ 行**。这类事只有真数据能验证规模。

**你怎么做（约 2 分钟）**

1. 打开手机上的「任务管家」（就是你平时用的那个，图标可能显示「任务管家 V4」）。
2. 进 **我的 / 个人中心 → 找到「备份」或「数据备份」**（不同版本文案可能叫「导出备份」）。
3. 触发一次备份。如果它让你填备份名称，**随便起个名**，比如 `real`。
4. 完成后告诉我「好了」。

> 如果找不到这个入口、或者点了报错，**直接告诉我**，我换别的路子（比如临时给你装一个 debug 版专门取库）。

**你要回我什么**
- 只要一句话：**「已备份」** 或 **「没找到备份入口」**（后者请描述你在个人中心里看到了哪些菜单项，我据此判断版本）。
- **不用**你把文件传给我——备份会落到手机的 `Download` 目录，我自己 `adb pull` 拿。

**我拿到后会做什么**
拉下来 → 脱敏（去掉可能含个人信息的任务标题）→ 作为第二份金样本 `golden-real.db` →
用它跑一遍 RN 的读库验收 → **用它替换合成样本作为 M1 各模块的验收基准**。

### A2 · 确认一件事：你的积分余额和任务大概是什么量级

**为什么需要**
回补规模决定了循环任务生成逻辑要不要加保护。我需要知道你的循环任务最早能有多早。

**你要回我什么**（一句话就行）
打开 App 看一眼，告诉我：
- 现在大概有多少个任务？
- 有没有在用「循环任务」功能？如果有，最早的那个大概排在什么时候？

> 如果你平时没怎么用循环任务，直接说「没在用」即可，那我就按「真实数据里没有循环任务」来验收，
> 循环回补的规模评估改用合成数据单独做。

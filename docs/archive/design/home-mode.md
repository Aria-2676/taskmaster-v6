# 可换首页（插件整页开屏即享）

> 2026-10-26 ｜ 状态：**已实现**（`lib/core/home/home_mode.dart`、`home_mode_store.dart`、`main_shell.dart`）
>
> 2026-10-27 补充：顶栏增加**快捷切换器**，并确定"`+` 只属于任务模式"。

## 0. 怎么切（2026-10-27）

| 入口 | 位置 | 行为 |
|---|---|---|
| 快捷切换 | 顶栏标题右侧的小箭头 | 底部弹层列模式，点一下即切，**不进设置** |
| 详细设置 | 侧边栏 → 首页模式 | 同一份清单 + 失败告警 + 解释文案 |

两处共用 `buildModeOptions()`（`lib/app/widgets/mode_switcher.dart`），
不各写一份 —— 各写一份的结果是"这里能选、那里选不了"，名字还迟早对不上。

**顶栏标题跟着模式变**：

- 内置任务模式：`10月26日 周一`（双击回今天）
- 插件模式：插件名（不给双击 —— 日历条都看不见，回"今天"没有意义）

**插件模式下 `+` 按钮直接不画**，而不是灰掉。主包不知道插件里"新建"是什么意思
（写日记？记一笔？），留一个 `+` 去建任务，用户会以为"新加的东西没存上"。
灰掉更糟：看着像哪里没配置对，而且会一直被点。切回任务模式就有 `+` 了。

## 1. 一条不能破的规矩：外壳归主包

换首页只换**内容区**。顶栏、侧边栏、底栏永远由主包画；
`+` 按钮也归主包决定——但主包可以决定**不画**（插件模式下就是如此）。

理由只有一个：插件崩了得有路可退。如果允许插件独占全屏当首页，
一个 JS 报错就等于应用打不开，用户连"去哪儿关掉它"都找不到。

## 2. 两种首页实现，各有各的天花板

| 实现 | 手感 | 适合 |
|---|---|---|
| 内置任务模式（原生） | 原生 | 默认 |
| 插件整页（WebView） | 明显打折：滚动、动效、键盘 | 内容形态主包预料不到的（备忘录） |

不要用 WebView 去做"任务列表的另一种排布"：那种需求本质是数据驱动，
交给主包的原生列表更划算。现在没实现"原生渲染 + 插件给规则"的第三种，
是因为还没有具体需求逼它 —— 真有了再加，不预留。

## 3. 开屏时序

| 时刻 | 发生什么 |
|---|---|
| 0 ms | 外壳起来：底栏/顶栏立刻可点 |
| 启动时 | **第一帧之前**读好 `ui.home_mode` 与字段偏好（否则会先画内置再跳插件，闪一下） |
| ~100 ms | 插件资源从本地解压目录 `file://` 加载，不走网络 |
| onPageFinished | `PluginView.onLoaded` → 取消超时计时器 + 标记本次会话成功 |

加载期间显示内置首页，不显示空白页 —— 外壳先出，内容后到。

## 4. 熔断（三件套，缺一不可）

插件把启动拖死时用户没有界面可用，所以判断必须在**渲染之前**就能做：

1. **上次会话没走到"首页渲染成功"** → 启动时记一次失败。
   实现：`sys.session_clean` 启动写 `0`，首页真的呈现（内置首帧或插件 onPageFinished）才写 `1`。
2. **本次首帧超时 2 秒 / 加载报错** → 立即换回内置首页 + 一条提示，并记一次失败。
3. **连续失败达到 2 次** → 自动切回内置并**落库**，`首页模式` 页显示红色提示。

计数在一次成功渲染后清零，所以偶发一次崩溃不会把用户的首页永久换掉。
失败后本次会话不再重试（否则每次通知都会重新加载，首页会不停闪）。

## 5. 失败会怎么表现

- 插件被卸载：直接回内置，不提示（用户自己卸的，不需要吓他）。
- 插件打不开：底部一条 3 秒提示，内容区是内置首页。
- 自动降级：`首页模式` 页顶部有橙色警告，写明失败次数，可以手动再选回插件。

## 6. 还没做

- 插件页常驻预热（当前每次进首页重新加载；实测冷启动超过 800ms 再考虑）。
- 插件崩溃的运行时捕获（现在只认"首帧没完成"，页面加载成功后崩掉不算）。
- 通知能力（备忘录要提醒的话，得由主包代发，插件申请不了权限）。

## 7. 真机验证时踩到的三个坑（都已修，别再犯）

**① 冷启动不生效：只听 homeStore 不够。**
已装插件列表是异步读库的，`initState` 那一刻 `installed` 还是空的，
`_syncHome` 找不到插件就直接返回，之后再没人叫它 ——
表现是"设了插件首页，当场生效，重启就回内置"。
**必须也监听 `marketStore`**，它 refresh 完成后会 notify，这时再决定首页是谁。

**② `markRendered` 把失败计数清零，导致"两次失败降级"永远不触发。**
两个来源：
- 启动初期插件还没加载出来，内置首页先顶上，被当成"成功渲染"；
  现在只有 `mode.isBuiltin`（用户本来就要内置）才算成功。
- 加载失败时 WebView **仍然会回调 `onPageFinished`**（错误页也算加载完成），
  于是 `onLoaded` 把计数清零。现在 `_homeDisabledForSession` 一旦为真就忽略该回调。

**③ 首页挂掉后整屏只剩下内置首页 + 一条提示，但设置里看不出发生过什么。**
`首页模式` 页顶部的橙色警告 + 失败次数是从 `sys.home_failures.<id>` 读的，
降级时不清理这个计数，就是为了让用户知道"为什么被切回来了"。

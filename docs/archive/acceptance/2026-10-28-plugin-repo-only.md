# 验收 · 能量改成"只从仓库分发"（2026-10-28）

> 对应提交：本文件所在提交（本地，**未推送**）
> 环境：`emulator-5554`，本轮重新构建的 debug 包
> 结论：**待签收**（只有 1 条要你判断，见 B1）

## 为什么改

上一轮"货架联网"只验到了索引那一层：两个插件都随包打进 APK，所以装的时候
永远走的是 asset 分支，**远端下载那条路径一次都没跑过**。把能量挪出去之后：

- 它变成真正的"仓库插件"：以后升级它只需要 push 新包，不用发版
- APK 顺带小了 4 KB（以后插件多了这个差别会明显）
- 远端取包这条路径有了真实用例

## 规则：**路径就是分发方式**

| 路径 | 打进 APK | 谁在用 |
|---|---|---|
| `assets/plugins/<id>_v<ver>.zip` | 是 | 随包兜底，断网也能装（现在只有「使用说明」） |
| `plugins/packages/<id>_v<ver>.zip` | 否 | 仓库分发，装的时候联网下载（现在只有「能量」） |

- 谁只走仓库由 `tool/make_demo_plugin.py` 的 `REPO_ONLY` 决定
- 打包脚本会顺手删掉另一边的旧包（不然"改成仓库分发"之后 APK 里还躺着旧的）
- `asset_index_test` 加了反向断言：同一个包两边都有就变红

## 零、已自测（机器判定）

| # | 断言 | 证据 |
|---|---|---|
| A1 | 索引里每个包的 sha256/size 与实际文件一致；随包的读 asset、仓库的读磁盘 | `asset_index_test` › 每个包的体积与 sha256…（随包的读 asset，仓库分发的读磁盘）✔ |

## 一、真机实测（我跑的）

| 步骤 | 预期 | 实测 |
|---|---|---|
| 1. `unzip -l app-debug.apk \| grep plugins/` | 只有 `demo_help_v1.4.0.zip` 和 `index.json`，**没有** energy 的 zip | ✔（`unzip -l \| grep -c energy_currency` = 0） |
| 2. 装新包 → 市场 → 卸载能量 | 已安装剩 1 项，能量进入「可安装」 | ✔ |
| 3. **断网**状态下点安装 | 失败，并且错误里能看出它在**解析域名** | ✔ 提示条：`下载失败：所有源都不可用（… SocketException: Failed host lookup: 'raw.githubusercontent.com' (OS Error: No address associated with hostname, errno = 7)）` |
| 4. **恢复网络**，同一个包再装 | 从 jsDelivr 下下来并装成 1.0.0 | ✔ `files/plugins/energy_currency/1.0.0` 落地 |
| 5. 看首页顶栏 | 闪电徽章回来（⚡0） | ✔ |

第 3、4 步是一组 A/B：**同一个 APK、同一个索引，只改网络**。
断网时它连本地兜底都找不到（DNS 都解析不了），联网就装上了 —— 字节只能来自网络。

### 这条验证的边界（要说清）

第 3、4 步走的是 `assets/plugins/energy_currency_v1.0.0.zip` 这个**已经在远端**的旧路径
（上一次推送留下的）。它证明的是"APK 里没有的包，装的时候真的去网上取"，
**不等于**新路径 `plugins/packages/…` 也验过了 —— 那条要等这次推送之后才能跑。

| # | 路径 | 操作 | 预期 | 不过时先看 |

## 三、已知限制 / 注意

- **`plugins/packages/` 这条路径还没推到远端**。在推送之前，远端索引（缓存里的）
  仍指向旧的 `assets/plugins/…`，那个文件在远端还在，所以现在装能量**照样能成**
  （走旧路径）。推送之后远端索引改指新路径，也能成 —— 两条路都不空。
- 过渡窗口：推送那一刻如果 jsDelivr 缓存还没刷，会有"索引指着已删的旧路径"的
  短暂状态。**推完立刻跑 `tool/purge_jsdelivr.ps1`**（脚本已就绪并试跑通过）。
- 能量现在不能离线重装了（它是仓库插件）。这是有意的取舍：随包 = 离线可用但升级要发版。

# 后续开发路线图

> 最后更新：2026-11-01

## 0. 这份文档怎么用

- **只定“做什么、为什么、什么时候算完成”，不承诺日历日期。** 版本号只是阶段标签，
  出口条件没达成就不能发版。
- 用户 2026-11-01 定下的优先级是四条线：**插件平台完善、番茄钟（补齐 V5 能力）、
  统计/回顾、任务能力深化**。四者可并行排，但依赖顺序见 §6。
- 改方向先改本文，再去 `docs/decisions.md` 记“为什么这么定、否掉了什么”。
  本文不写取舍理由，避免同一件事出现两份口径。
- 代码是事实。本文的“现状”若与代码冲突，先改本文，再改认知。

## 1. 当前基线（事实）

| 项 | 现状 |
|---|---|
| 版本 | `6.0.6+6006`（以 `pubspec.yaml` 为准） |

## 2. 方向判据

1. **先数据后界面，先可用后好看。** 数据语义没定清楚之前，不做只为好看的页面。
2. **插件优先，但不是为插件而插件。** 能满足“插件能提供主包没有的东西”才做成插件；
   只是主包内部的呈现策略（如日历条形态）放设置项，不包装成插件。
3. **主包只做三类事**：被两个以上插件依赖的框架、需要系统能力的底座、数据一致性的唯一入口。
4. **没有插件也必须完整可用。** 插件只能加分，不能成为使用前提（软依赖只引导，不阻塞）。
5. **不为了“平台感”牺牲可诊断性。** 能拿到原始错误就露原文；失败要能定位到文件/状态。
6. **手感与平台层问题只认真机/模拟器。** widget test 锁“有没有这个特征”，锁不住“点不点得着”。
7. **不换栈、不引入运行时 Dart 加载、不走上架。** 这三条已被证伪或明确否决，见
   `docs/INDEX.md` 的“已证伪”清单与 `docs/decisions.md`。
8. **主包造能力，插件造功能。** 主包的产物是"能被插件调用的能力"（计时、通知、任务读写、
   存储、事件），不是这些能力的界面。**用户看得见的功能优先交给插件**；主包只在
   "两个以上插件都要用"或"必须系统能力/数据一致性"时才自己出面。
9. **能力有版本，插件可以要求最低主包版本。** "这个插件需要 6.1.0+" 是合理事实，
   不是缺陷 —— 缺的能力就该装不上或明确提示，不能让用户装完发现按钮点了没反应。

## 3. 版本与出口策略

| 类型 | 用途 | 出口条件 |
|---|---|---|
| `6.x.0` | 一条主线的能力里程碑 | 该节列出的全部出口条件通过，且有可量化验收清单 |
| `6.x.y` | 修复、插件平台小步完善、插件上新 | `flutter analyze lib` 无 error + 全量测试通过 + 用户签收 |
| 插件版本 | 插件独立发版 | 打包幂等、索引 sha/size 重算、市场可见、不要求发 App |

**版本号纪律**：`versionCode` 只能涨；发版顺序永远是“先传包、最后改 `update.json`”；
被引流入口写死的版本冻结，不再重发，见 `docs/conventions/delivery.md`。

## 4. 主线

> **当前主排期是 4.5（P5 五模式，占 6.2~6.8）**。4.1 已完成（6.1.x）；
> 4.2 / 4.3 的版本号已让位给 4.5，内容并入或顺延；4.4 是贯穿所有版本的平台线。

### 4.1 P1 · 时间与专注（番茄钟，6.1.0 候选）

**目标**：补上 V5 的番茄钟能力，同时把“后台计时 + 通知 + 事件落库”这套系统能力底座建好。
这是统计线的数据来源，也是任务提醒的前置。

**范围**

| 件 | 归属 | 要点 |
|---|---|---|
| 计时引擎 | 主包 | 开始/暂停/继续/重置；专注/短休/长休/间隔；只存“正在计时”的运行时状态 |
| 前台服务/通知 | 主包 | 后台与进程被杀后仍能到点通知；通知渠道、权限引导；国产 ROM 的例外要写明 |
| 会话结束钩子 | 主包 | 接通 `pomodoro.sessionFinished`，payload `{mode, durationSeconds, actualSeconds, taskId?}` |
| 番茄钟插件 | 插件 | 页面 UI、设置、`plg_pomodoro_records` / `plg_pomodoro_settings`；订阅钩子 + `event.pending`，按事件 id 幂等 |
| 任务关联 | 主包 + 插件 | 可选 `taskId`；完成任务与专注会话的关联展示走插槽或插件页，不改主包任务字段 |

**出口条件**

- 25 分钟专注在**退到桌面**后仍走完，并在到点发通知；杀进程后重开，通知仍按计划触发。
- 暂停期间不计入 `actualSeconds`；`actualSeconds` 与实际有效时长一致（可用数据库断言）。
- 插件未安装时**看不到番茄钟入口**（主包只提供计时能力，不提供界面）；
  装上插件后，会话记录写入插件的 `plg_pomodoro_records`。
- 插件未挂载时发生的事件，下次挂载能补发且不重复发奖（按事件 id 幂等）。
- 通知权限被拒绝时，有明确引导；不出现“计时在跑但永远不通知”的静默失败。
- 真机/模拟器证据：至少一台 Android 12+ 设备的后台/杀进程场景。

**明确不做**：桌面小组件（另立候选）；统计页面（下一阶段）；云同步。

### 4.2 P2 · 统计与回顾（**版本号让位给 4.5**，顺延到 6.9+）

**目标**：让用户看得到“完成率、专注时长、趋势”，而不是只看到任务列表。
统计是跨域数据（主包任务 + 番茄钟插件），**不能靠插件直接读主包表**。

**必须先定的架构选择**（写进 `docs/decisions.md` 后再实现）：

| 方案 | 做法 | 代价 |
|---|---|---|
| A（建议） | 主包 bridge 增加**只读统计查询**（白名单指标 + 日期范围 + 分页），插件拿聚合结果 | 要设计稳定的指标契约；契约版本可能要 +1 |
| B | 统计插件用事件（`task.completed` / `pomodoro.sessionFinished`）维护自己的汇总表 | 装插件前的历史数据要回填；事件漏了会失真 |
| C | 统计做成主包页面，不做插件 | 违背“可选功能插件化”，但实现最简单 |

**范围**：日/周/月完成率、专注时长、连续天数、标签分布、空态与无数据态；
查询必须有上限/索引，不做全表拉回内存。

**出口条件**

- 统计数字与手工 SQL 对账一致（至少 3 个日期范围、含跨月/空数据）。
- 1 年/1 万条任务量级样本上，首屏查询不触发全表扫描（用 `EXPLAIN` 或等价证据）。
- 装/卸统计插件不影响主包任务数据；卸载默认保留数据，删数据要明确提示。
- 没有插件时主包仍有最基本的“今日完成数”，不出现空白页。

**依赖**：6.1 的番茄钟数据；任务完成事件；统计读取模型。

### 4.3 P3 · 任务能力深化（**版本号让位给 4.5**；循环/提醒/附件并入对应模式版本）

拆成两批，避免一版塞太多。

#### 6.3.0 候选：循环任务 + 搜索

- **循环任务**：日/周/月；生成窗口与幂等（`loop_id` + 同日去重）；模板与实例的边界；
  编辑/删除模板对已生成实例的影响；bridge 支持。
- **搜索**：标题/描述/标签；与现有筛选同一数据流（V5 的“两套结果排序不一致”教训）；
  空态可达；性能上限。

**出口条件**

- 同一模板同一天只生成一条；跨多天回补不重复、不丢；改模板不篡改历史实例。
- 搜索受当前标签/日期筛选约束；排序与主列表一致；无结果空态可达。
- 迁移测试：造一个旧库再打开，循环字段与索引正常。

#### 6.4.0 候选：任务提醒 + 附件

- **提醒**：任务级提醒时间；通知调度；完成/删除时取消；权限与国产 ROM 引导。
- **附件**：图片/文件；大小上限；本地存储；备份与恢复；删除任务时的清理。

**出口条件**

- 提醒在进程被杀后仍触发；改时间/完成/删除后旧提醒不重复。
- 附件随备份/恢复往返；卸载/删任务不留下孤儿文件；超限有明确拒绝文案。

> 附件如果评估后成本明显高于收益，可移到候选池，不阻塞 6.3/6.4 的其他能力。

### 4.4 P0 · 插件平台完善（贯穿 6.x.y，不单独占一个 minor）

平台承诺是“不发 App 版本也能上新/改插件”。这条线不追求一次做完，按小步持续补。

| 项 | 出口条件 | 优先级 |
|---|---|---|
| 契约治理 | `docs/plugin-contract.md` 与代码逐条一致；契约版本 +1 的判据写死；有契约测试 | 高 |
| 索引签名 | `index.json.sig` 离线私钥签名，App 内置公钥验签；篡改索引会被拒绝 | 高 |
| 插件作者文档 | 不读源码也能写出可安装插件：清单、权限、bridge、storage、事件、打包、发布 | 高 |
| 商店体验 | 已装/可装/升级/停用/卸载/失败重试/离线状态都有人话；不出现“未知权限” | 中 |
| 故障隔离 | 插件崩/超时/白屏不拖垮外壳；首页熔断可回退；WebView 升级后不吃旧缓存 | 高 |
| 主题包 | `theme.json` 资源热更 + 预览/回退；不改 Dart 代码 | 中 |
| 分发 | 插件打包幂等；索引 sha/size 由脚本算；`REPO_ONLY` 例外清单；CDN 缓存不骗人 | 高 |
| 诊断 | 插件页可看版本/契约/权限/最近错误；日志可导出（本地） | 中 |

**平台硬约束**（不要试图突破）：插件不能提供 Dart UI；区域级插槽只改数据不改皮；
服务级只开白名单；插件表只能 `plg_<id>_*`；永不执行插件传来的 SQL。

### 4.5 P5 · 五模式与今日页（2026-11-03 定，占 6.2~6.8）

**背景**：把"任务/清单/计划/日记/备忘"做成同一套数据能力上的不同心智视角，外加一个
今日聚合页。三条前提决策已进 `docs/decisions.md`：请求式查询、今日页内嵌 + 块级容错、
计划模式放宽建表。

**为什么插到最前面**：这是产品主形态。原 4.2（统计）与 4.3（任务深化）不是被砍，
而是**让位**——任务的循环/提醒/附件在对应模式版本里顺带做，搜索在 6.8 统一收口。

**版本序列**（`6.x.0` = 里程碑；内部真会拆补丁版本，但只拆近期，远期不预排）

| 版本 | 主题 | 出口条件 |
|---|---|---|
| 6.2.0 | 数据交互层 | 计划模式能响应查询；契约文档 + 守卫测试；不实现的插件不参与 |
| 6.3.0 | 今日页 + 底栏 | 底栏「首页·今日·我的」、`+` 挪顶栏；不装插件也有今日任务；单块超时不卡整页 |
| 6.4.0 | 备忘（新插件） | 快速记、置顶、转任务；今日页出现"置顶备忘"块 |
| 6.5.0 | 清单升级 | 清单库/模板/复用；清单项可转任务；不再只是"读任务的筛选视图" |
| 6.6.0 | 计划重建 | 计划/阶段/里程碑建表；任务可排入；进度可见 |
| 6.7.0 | 日记 | 日历热力图 + 日期流；富文本/图片/心情；可引用当天任务 |
| 6.8.0 | 全局搜索 + 关联 | 一次搜索跨模式出结果；备忘→任务→计划可跳转 |

**近期两步拆细**（马上要做，能排准）

```

6.2.3  失败记忆（连续 2 次本会话跳过）+ 界面「部分模式未接入」
```

**已拍板的四条**

1. 今日页第一屏：今日任务 + 今日计划 + 置顶备忘；后续向「可编辑」发展。
2. 日记**一日多篇**（按时间流，不按日期唯一）。
3. 清单与任务**可串联**（清单项可转任务 / 任务可关联清单）。
4. 6.2 先做"能被查"最小版，通用性留到 6.3 再抽象——先跑通一条，别一上来设计协议。

**风险**：跨 WebView 查询是全新的调用模型，超时/并发没做过；今日页懒加载手感要真机验。

## 5. 发布与运维（P4，随版本搭车）

- **后台检查更新**：现在只在启动检查一次；补周期检查/回前台重试的产品化方案。
- **更新说明展示**：当前版本也能看到“我在用什么版本”，不只在新版本弹窗里。
- **备份 S3**：用户可选目录（SAF）、超量旧备份一键删、是否加密（需定案）。
- **发布链加固**：`publish_release.ps1` 的纯 ASCII 包装、BOM、notes JSON、Gitee 手动传包、
  摘要回读；把踩过的坑固化成检查清单。
- **诊断**：本地日志导出、插件/更新失败的可复制错误信息。

**出口条件**：一条命令能完成“构建→上传→改清单→刷缓存”，只剩 Gitee 手动上传一步；
冷启动/后台两种场景都能收到更新提示；备份能跨设备恢复且报告丢失项。

## 7. 风险登记

| 风险 | 触发表现 | 对策 |
|---|---|---|
| 多 agent 上下文分叉 | 两份“最新”结论、重复实现、互相覆盖 | 仓库为唯一共享记忆；开工先读 `docs/ai/README.md`；任务文件 claim；接口变更写决策 |
| 统计全表扫描 | 数据一多就卡；内存暴涨 | 只读统计契约 + 索引 + 上限；用样本量测 |
| 后台计时被 ROM 杀 | 计时不走、通知不来 | 前台服务 + 权限引导 + 真机矩阵；验收必须含杀进程 |
| 数据迁移 | 升级用户崩溃/丢数据 | 每条迁移配“造老库再打开”的测试；低于目标补一步 |
| 契约漂移 | 插件装不上/行为不一致 | 契约测试 + 版本 +1 判据；索引/包内清单一致性守卫 |
| 发版链 | 清单先改、包没传；PowerShell/BOM/中文路径 | 固定顺序 + 纯 ASCII 包装 + 检查清单 |
| CDN 缓存 | 旧索引/旧清单 | 并发取多份按时间戳取最新；`publishedAt`；不假设镜像一样新 |
| 公开仓库泄密 | token/密钥/真实数据入库 | `.gitignore` 纵深防御；提交前 `git status --untracked-files=all` |
| 平台层“看得见点不着” | widget test 全绿、真机点不中 | 弹层/键盘/Insets 类必须真机验收；坐标先 dump 再点 |
| 跨插件查询超时 | 搜一次/开一次今日页卡住 | 单次 1.5~2s 超时；失败记忆；部分结果要明说 |
| 今日页首屏变慢 | 进页面就打 N 个 IPC | 主包部分先出；插件块懒加载（滚到可见才请求） |
| 范围膨胀 | 一版塞太多、出口模糊 | 每条主线独立出口；候选池只记录不排期 |

## 8. 候选池（记录，不排期）

- 商城、积分货币、刮刮乐、小游戏：V5 老功能，做成插件的候选；先等货币/商品体系定案。
- 桌面小组件：需要原生能力，主包做；优先级低于番茄钟。
- 主题包/设计 token：资源热更成熟后再做。
- 任务模板、日历集成、云同步：与“离线为主、零持续费用”冲突或成本高，暂缓。
- Web / iOS / 上架：**不做**。iOS 从未构建；上架会重新引入商店审核与热更限制。

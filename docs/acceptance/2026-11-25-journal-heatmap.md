# 2026-11-25 日记热力图（6.7 收尾）验收

## 做了什么

日记页顶部加日历热力图：最近 24 周（168 天）的写作密度，7 行 = 一周七天，
颜色四档（0 / 1 / 2 / 3+ 篇），未来日期不画。下方一行「这个月写了 N 天」。

**为什么值得做**：日记是唯一一个「有没有坚持」比「写了什么」更重要的模式。
日期流只能看见写了的日子，看不见漏掉的日子 —— 热力图把「空档」也摊在眼前。

### 上一版的两个错（1.0.3 → 1.0.4）

1. **把篇数当天数**：`monthDays++` 写在了遍历每条记录里，同一天三篇算成三天，
   于是「这个月写了 8 天」而实际只有 5 天。改成用 `day` 去重后再数。
2. **18 列只有 234px**：右边空一大条，看着像没画完。改成 24 列（168 天）。

## 「可引用当天任务」的现状与取舍

`loadDoneTasks()` 已经在做：写日记时显示「今天完成：A、B」，**只读，不写进日记**。

这轮**不做**持久化引用，理由：

- 要存就得加表（插件的 storage 只 `CREATE TABLE IF NOT EXISTS`，加列不生效），
  再配选中 UI 和编辑态回填，成本不小
- 而它要解决的问题（"写日记时想不起来今天干了啥"）已经由只读提示解决了
- 存快照还会引出"任务改名了，日记里显示旧名字对不对"的语义问题 —— 没有真实需求前不引入

如果以后要做，方向是新建 `refs` 表存 `entry_id + task_id + title 快照`，
显示时用快照而不是实时查任务。

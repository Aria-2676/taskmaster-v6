# 设置面板与备份系统（V6 设计）

> 2026-10-29 ｜ 状态：**设计已定，待实现**（S1/S2/S3）
> 定位：V5 的同类功能只作参考，**内容与语义按 V6 重做**。V5 的备份是"整库拷
> .db"，V6 是"分段 JSON 打包"，两者不通用、也不该硬套。

## 1. 三个地方各管什么

先定职责，再定内容 —— 否则每加一个功能都要重新吵一遍位置。

| 位置 | 一句话职责 | 放什么 | 不放什么 |
|---|---|---|---|
| 侧边栏 | **去哪儿**（导航） | 今日任务、回收站、标签管理、字段管理、插件市场、首页模式、设置、关于 + **已启用插件的入口** | 低频操作、任何开关 |
| 我的 | **我是谁 + 一眼现状** | 当前货币、装了/启用几个插件、任务与回收站条数、上次备份时间、快捷入口 | 具体开关 |
| 设置 | **怎么工作**（配置） | 五个分组：外观 / 任务 / 插件 / 数据 / 关于 | 内容浏览、任务操作 |

**同一个功能可以有几个入口，也可以只有一个角落**，按"它是不是增长点"判：

| 功能 | 入口数 | 理由 |
|---|---|---|
| 插件市场 | 3（侧边栏 / 设置→插件 / 我的→已装插件） | 内容是持续增长的，值得多给入口 |
| 首页模式 | 2（侧边栏 / 顶栏切换） | 高频切换，但设置里只做只读 + 跳转 |
| 标签、字段管理 | 2（侧边栏 / 设置→任务） | 属于任务配置，两处都合理 |
| **数据备份** | **1（设置→数据）** | 低频。"我的"里只留一句 `上次备份 3 天前`，点它跳设置，不给按钮 |
| 关于 / 检查更新 | 2（侧边栏 / 设置→关于） | 手动反悔路径，不能省 |

设置页的五个分组：

- **外观**：日历条形态、编辑页形态（sheet / 全屏）
- **任务**：删除前确认、删除后先进回收站、回收站保留时长、字段管理入口
- **插件**：插件市场、已装插件（启用/停用在此或市场里）、首页模式、当前货币
- **数据**：**备份与恢复**、打开备份目录、清空回收站
- **关于**：版本信息、检查更新、帮助/使用说明

## 2. 备份文件格式

**一个 zip，里面两个 json**（扩展名用 `.zip`，分享出去任何客户端都认）：

```
taskmaster-v6-backup-20261029-0015.zip
├── manifest.json   ← 小、可读：格式版本、创建时间、App 版本、各段条数、包含项
└── data.json       ← 全量：tasks / tags / settings / plugins.<id>
```

- `manifest.json` 单独拆出来的理由：备份列表页只需要摘要，不必把几 MB 的
  `data.json` 解出来再数一遍。
- 用户想"看一眼里面是什么"，解压就能读，不用任何工具。

**不给"格式开关"**（JSON / zip 二选一）：格式是程序之间的契约，不是口味。
一旦支持两种，导入端要维护两套解析、两套测试，而用户选错的唯一后果是
"我导不进去"。想要可读性，上面这个结构已经给了。

**体积**：几百条任务 ≈ 几十 KB，压缩后更小。真到几 MB 再说分片，现在不为它设计。

## 3. 备份范围与勾选

勾选清单（新建备份时）：

| 段 | 默认 | 说明 |
|---|---|---|
| 任务 | ✅ | 含已完成/未完成；回收站里的默认**不**含（单独一项） |
| 标签 | ✅ | 含任务-标签关联 |
| 设置 | ✅ | `settings` 表里的主包键（不含更新器状态这类机器状态） |
| 回收站 | ❌ | 明确是可选项，默认不占体积 |
| 每个插件一行 | ✅（**已装**且有数据的） | 显示插件名 + 数据行数；停用的也勾上，标「已停用」 |
| 「已卸载，数据还在」那一行 | ❌ **默认不勾**（2026-10-29 用户定） | 列出来、可勾、标清「已卸载，数据还在」；勾选区下方提示「N 个插件的遗留数据未选」 |

**"有数据"的判据不是"装了没装"，而是"库里还有没有它的表"。**

卸载插件时可以选"保留数据"，那时表还在、KV 还在，只是插件不在已装列表里。
按"装了没装"判断，这些数据会**从清单里整个消失** —— 所以清单要能列出它们：
**「能量（已卸载，数据还在）」**。

但**默认不勾**（用户定）：这类数据属于"上次卸载时已经决定不要那个插件了"，
默认带上会让备份体积和恢复范围悄悄变大。不勾不等于不管 —— 勾选区下方要提示
「有 N 个插件的遗留数据没选」，让用户知道自己放弃了什么。

## 4. 恢复规则

选文件 → 解析 `manifest.json` → 逐段勾选 → 二次确认 → 执行 → **恢复报告**。

默认勾选规则：

| 情况 | 默认 | 可改 |
|---|---|---|
| 任务 / 标签 / 设置 | ✅ 全勾 | 可取消 |
| 备份里有、当前**已装**的插件 | ✅ | 可取消 |
| 备份里有、当前**未装但表还在**（卸载留了数据） | ❌ **默认不勾**（同备份） | 可勾 |
| 备份里有、当前**未装且表不存在** | ❌ **禁用**，附一句「先装上这个插件再恢复」 | 不可 |

最后一行是最容易出事的：目标表不存在时强行写入，要么静默丢数据，要么建一张
和插件 schema 对不上的表，插件装上后一读就崩。

**冲突策略：覆盖**（首版）。合并要处理任务 id 冲突、标签重名合并、插件主键
冲突，容易做成半成品；先给"覆盖 + 说清会丢什么"，比给一个不完整的合并安全。

二次确认必须写具体数字：「将覆盖当前的 128 条任务、6 个标签、2 个插件的数据」，
而不是「确定恢复吗？」

**恢复报告**：恢复完给一页结果——每段写入多少条、丢弃了哪些列（见 §6）、
哪些插件因为没装被跳过。不是一句"成功"。

## 5. 版本管理与分享

- **列表**：时间、大小、摘要（`任务 128 · 标签 6 · 插件 2`）、操作 = 详情 / 恢复 / 分享 / 删除
- **保留策略**：默认保留最近 **20 份**；超了**提示**，不自动删（备份是用户的退路，
  自动删等于替他做决定）
- **分享**：系统分享面板（`share_plus`）。这是"App 私有目录用户看不见"的唯一正路
  —— 微信也一样，它也只能通过系统面板让用户转存，不能自主写用户的目录
- **备份位置**：默认 App 专属外部目录；另给「选择一个文件夹」走系统目录选择器（SAF），
  用户选了就长期写在那儿（比如"下载"）。这是 Android 11+ 唯一能"让用户看得见"的正规做法
- **隐私提示**：分享前提醒一句「这个文件里有你的全部任务正文」——备份天然是敏感数据，
  且没有加密

## 6. 已知风险（实现时必须处理）

| 风险 | 处理 |
|---|---|
| 插件表结构变了（备份是旧版本打的） | 恢复按**当前装着的那版** manifest 建表/迁移，再灌数据 |
| 备份里的列在当前 schema 里不存在 | 丢弃该列，记进恢复报告（**不静默**） |
| 数据量大（几千条） | 解析放到 isolate，UI 显示进度；首版可以先同步，但要留出可换的边界 |
| 备份文件损坏 / 不是本产品的 | 解析失败要报"这不是任务管家的备份文件"，别抛原始异常 |

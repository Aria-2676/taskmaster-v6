# 文档维护

> 最后更新：2026-11-01

## 什么时候用

- 新增设计/规范/验收/路线图文档
- 修正过时断言、拆超长文档、归档已结束的内容
- 发现同一规则出现在多处，需要收敛

## 步骤

1. **先判断这份内容该放哪**
   - 规则 → `docs/conventions/`（唯一源）
   - 取舍/原因 → `docs/decisions.md`
   - 计划/出口 → `docs/ROADMAP.md`
   - AI 流程 → `docs/ai/`
   - 验收 → `docs/acceptance/`（签收后移 `docs/archive/acceptance/`）
   - 已实现的设计 → `docs/archive/design/`
2. **查重**：同一句话是否已经在别处？有就改那份，不要新增副本。
3. **写时间戳**：标题下加 `> 最后更新：YYYY-MM-DD`；**不回填旧文档**。
4. **更新 `docs/INDEX.md`**：文件分工表加一行，说明负责什么、什么时候读、状态。
5. **被证伪的断言**：删掉原文，在 INDEX 的“已证伪”表留一行“曾这么写过、为什么错”。
6. **归档判据**：这份文档描述的功能/版本/一次交付**已经结束** → 移入 `docs/archive/`；
   还在改 → 留 `docs/` 根。
7. **行数**：常读文档单篇超过约 200 行就拆开，细节移入归档或独立文件。
8. **Markdown 结构**：引用块后要有空行，否则下一段会被吞；代码围栏必须闭合。
   可以跑 `python tool/check_md_blocks.py`（如存在）。
9. **链接**：用相对路径；归档后路径会变，按文件名搜，不要照旧路径找。

## 硬规则

- **规则唯一源**：不要在 `.trae/`、`CLAUDE.md`、`.workbuddy/`、README 里复制条文；
  只放 5 行指针。
- **证据优先**：文档里的命令/路径/版本必须自己跑过或来自代码；不要凭记忆写。
- **过时断言不保留**：不要写“留个参考”，它会在半年后误导排期。
- 归档区**只增不改**；历史记录不重写。
- 文件名只用 ASCII（内容可中文），否则 API 推送会失败。
- 不写无法判定的词（“正常”“流畅”“大概”）；要写成可观察事实。

## 输出

- 新增/修改的文档
- `docs/INDEX.md` 更新
- 必要的归档移动与链接修正

## 二、用户定下的三件事（按此顺序做，一件一验）

### 1. `system.info` 补 `version`（小，先做）

- 现状：bridge 只回 `{pluginId, contract, permissions}`，插件**无法知道自己的版本**，
  于是 `energy_currency/index.html` 里把 `v1.0.0` 写死了 —— 升级后会显示旧版本号。
- 做法：`PluginBridge` 加 `version` 入参（`_launchPlugin` 里 manifest 现成的），
  `system.info` 返回里加 `version`；顺手把 energy 插件页那行改成读 `system.info`。
- 注意：这是**加字段**不是改契约，`PluginContract.current` **不要 +1**（老插件不受影响）。
- 验收：升级后插件页显示的版本跟着变。

### 2. 插件停用 / 启用（中）

- 现状：`InstalledPlugin.enabled`、`PluginStore.setEnabled()` 都在，**界面没接**。
- 语义要定清楚（先问用户，别自己拍）：停用 = 隐藏入口 + 不推事件 + 不占首页/货币位？
  还是只隐藏入口？
- 落点：市场页已安装区加一个开关；`MainShell` / `SideNav` / `HookBus` 都要尊重它；
  停用后如果是当前首页或当前货币，要像卸载那样回落（复用 `onPluginUninstalled` 那条链）。
- 验收：停用后侧边栏入口消失、事件不再发给它、顶栏不再显示它的货币。

### 3. 联网插件货架（大，最后做，可拆）

- 现状：`_loadIndex()` 只读 `rootBundle` 的 `assets/plugins/index.json`，
  所以"升级"要等新 APK；`urlFor` 是 `Uri(scheme: 'asset')`。
- 目标：索引与包都从 GitHub 取，走 jsDelivr 多源 + Contents API 兜底（和 updater 同一套）。
- **先定案再动手**：缓存策略（拉不到用本地缓存，缓存也没有就只显示已安装）、
  失败时的文案、包体积上限（jsDelivr 单文件 ≤20MB）、要不要索引签名。
- 契约文档 `docs/plugin-contract.md` §6 已经写好了分发规则，照着实现，别另发明。
